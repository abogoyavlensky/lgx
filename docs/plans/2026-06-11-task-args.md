# Task Positional Args Implementation Plan

> **Status: COMPLETED** (2026-06-11) — see the implementation summary at the end.

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a custom task declare typed positional CLI args (`:args`) and reference them in `:sh`/`:run` step vectors as `:arg/<name>` placeholders, with strict arity and config-time validation.

**Tech Stack:** let-go (`.lg`), lgx's spec engine (`lgx/spec.lg`), lgx's own test runner (`lgx test`), bash e2e harness (`tests/e2e.sh`).

---

## Design

### Problem

Custom tasks cannot be parameterized: `lgx deploy prod` runs the `deploy`
task and silently drops `prod` (`dispatch` in `lgx.lg` never passes
`rest-args` to `cmd-task`). The only way to vary a task run is to edit
lgx.edn or fall back to raw shell.

### Solution overview

A task gains an optional `:args` key declaring positional args. Step
vectors may contain `:arg/<name>` keyword placeholders that are replaced
with the bound CLI values at execution time:

```edn
{:tasks
 {deploy {:doc "Deploy the app"
          :args [{:name :env
                  :type [:enum "prod" "staging"]}
                 {:name :version
                  :type :string
                  :default "latest"}]
          :do [{:sh ["./deploy.sh" :arg/env :arg/version]}
               {:run ["notify.lg" :arg/env]}]}}}
```

`lgx deploy prod` runs `./deploy.sh 'prod' 'latest'` then
`lgx run notify.lg prod`.

Approved semantics:

- **Trailing-optional defaults.** Args without `:default` are required and
  must precede args with `:default` (validated at config load). CLI values
  fill positions left to right; unfilled trailing args take their defaults.
- **Vector-form placeholders only.** A placeholder is a real
  `:arg/<name>` keyword item in a step vector — no string templating.
  String-form step values have no placeholder syntax.
- **Strict arity everywhere.** Surplus args are an error with a usage
  hint. A task without `:args` errors on any CLI args, replacing today's
  silent dropping.
- **Keyword `:name`.** Declared as an unqualified keyword (`:env`),
  referenced as the namespaced keyword `:arg/env`.
- **Shell-quoted substitution in `:sh`.** Each substituted value is
  single-quoted before the space-join, so it always arrives as one shell
  word and is never interpreted by the shell. Literal strings the user
  wrote in the vector stay verbatim. `:run` substitution is verbatim:
  each vector item is already one argv entry.

### Declaration rules (validated at config load)

All enforced in `config.lg` through the existing spec engine, using
`[:fn ...]` validators in the existing style (`coord-errors`,
`do-errors`). No changes to `lgx/spec.lg`.

- `:args` is an optional task key: a non-empty vector of closed arg maps.
- `:name` — required; an **unqualified keyword** (`:env`, not
  `:foo/env`), unique across the task's args.
- `:type` — optional, defaults to `:string`. Allowed: `:int`, `:string`,
  or `[:enum "v1" "v2" ...]` with at least two distinct non-blank
  **string** values (CLI values arrive as strings, so enums are
  string-only).
- `:default` — optional; must match the type: a string for `:string`, an
  integer for `:int`, one of the listed values for an enum.
- **Trailing-optional rule:** once an arg has `:default`, every later arg
  in the vector must too.
- **Placeholder cross-check** (task-level `[:fn]`, same pattern as
  `with-refs-errors`, running only after the structural check passes —
  `validate-and` short-circuits): every `:arg/*` keyword in the task's
  `:do` step vectors must name a declared arg. An `:arg/*` placeholder in
  a task without `:args` is an error. Unused declared args are allowed.
  The walk must handle both `:do` forms — a single step map or a vector
  of steps — because validation runs before `normalize-config`.
- **Step vectors widen:** items are strings **or** keywords with
  namespace `arg`. Any other keyword (bare, or another namespace) is a
  validation error in `action-value-errors`.

### Component 1: binding and substitution (`lgx/args.lg`, new)

Pure functions, unit-testable like `lgx/cli.lg`:

- `bind-args [decls cli-args]` → `{:bindings {:arg/env "prod" ...}}` or
  `{:errors ["..." ...]}` (message strings, all errors collected).
  - Arity: each missing required arg yields
    `missing required argument <env>`; surplus yields one error — when
    the task declares args,
    `too many arguments (expected at most 2, got 3)`; when it declares
    none, `task takes no arguments (got 2)`.
  - Types: `:int` validates via `parse-long` —
    `argument <port> must be an integer, got "abc"`; enum validates
    membership — `argument <env> must be one of: prod, staging, got "qa"`.
  - **All bound values are strings.** A provided `:int` keeps its original
    CLI string (no canonicalization); an unfilled arg binds `(str default)`.
  - Binding keys are `:arg/<name>` keywords. Implementation note: verify
    the let-go `keyword` arities first — `(keyword "arg" "env")` or
    `(keyword (str "arg/" ...))`, whichever let-go supports (see
    `docs/knowledge-base/let-go-stdlib-quick-ref.md`).
- `usage-line [task-name decls]` → `usage: lgx deploy <env> [version]`.
  Required args render `<name>`, optional `[name]`; with no decls just
  `usage: lgx deploy`.
- `shell-quote [s]` → `s` wrapped in single quotes with embedded `'`
  escaped as `'\''`. Always wraps, even when unnecessary — simple and
  predictable.
- `substitute [v bindings quote?]` → `v` with each `:arg/*` keyword
  replaced by its bound value (`shell-quote`d when `quote?` is true);
  string items pass through verbatim. An unbound placeholder throws
  `ex-info` — config validation makes this unreachable, so it is a
  programmer error, matching the spec engine's convention.

### Component 2: config validation (`lgx/config.lg`)

- New `arg-schema`: `[:and [:map {:closed true} ...] [:fn ...]]` — closed
  map with `:name` / optional `:type` / optional `:default`, then a
  cross-key check that `:default` matches the (defaulted) `:type`.
- New `args-schema`: `[:and [:vector {:min 1} arg-schema] [:fn ...]]` —
  duplicate-name and trailing-optional checks.
- `task-schema` becomes `[:and [:map {:closed true} ... [:args
  {:optional true} args-schema]] [:fn task-placeholder-errors]]`.
- `action-value-errors` widens vector items to string-or-`:arg/*`-keyword
  with message
  `must be a string or :arg/<name> placeholder, got <value>`.

### Component 3: execution wiring (`lgx/tasks.lg`, `lgx.lg`)

- `dispatch` passes `(vec rest-args)` to `cmd-task`.
- `cmd-task` calls `args/bind-args` **before** building the basis (cheap
  validation first, same principle as `cmd-test`'s missing-`test/`
  check). On errors it prints each as `lgx: <task>: <msg>` plus the usage
  line to stderr and exits 1:

  ```
  lgx: deploy: argument <env> must be one of: prod, staging, got "qa"
  usage: lgx deploy <env> [version]
  ```

- `tasks.lg`: `run-task!`, `run-step!`, `run-sh-step!`, `run-run-step!`
  gain a `bindings` parameter. `run-sh-step!` substitutes a vector value
  with quoting before the space-join; `run-run-step!` substitutes without
  quoting before handing the vector to `as-arg-vec`. String-form values
  are untouched. The echoed step line shows the substituted command, so
  the step header and `--verbose` reflect the real invocation.

### Component 4: help output (`lgx.lg`)

`task-line` renders the signature after the task name:
`lgx deploy <env> [version]  Deploy the app`. A long left column falls
back to the existing two-space separator.

### Error handling summary

- Config load: declaration shape, trailing-optional violations,
  default/type mismatches, duplicate names, unknown placeholders, bad
  keywords in step vectors → the existing `errors-report` path
  (collected, clean, exit 1).
- Runtime: arity/type/enum errors → stderr with usage line, exit 1.

### Testing strategy

- `test/lgx/args_test.lg` (new): bind-args arity/types/enums/defaults,
  shell-quote, substitute for both quoting modes, usage-line.
- `test/lgx/config_test.lg`: new schema rules, valid and invalid cases.
- `tests/e2e.sh`: happy path with `:sh` + `:run` substitution, default
  filling, type error with usage line, args passed to an argless task,
  shell-quoting of a hostile value, help signature rendering, config
  validation of a misordered `:default`.

## Implementation summary (2026-06-11)

All 8 tasks completed across commits 0dbe5c9..b281085. Implemented as
designed: `lgx/args.lg` (bind-args, usage-line, signature, shell-quote,
substitute), `:args`/placeholder validation in `config.lg`, bindings
threaded through `tasks.lg`, strict CLI binding in `cmd-task`, help
signatures, six e2e scenarios, README + ARCHITECTURE docs. Final state:
352 unit tests and 255 e2e assertions pass (`make test`).

Deviations from the plan, all minor:

- The Task 5 smoke check could not run in dev mode from a temp dir
  (`lg lgx.lg` resolves lgx's own namespaces relative to CWD, and a
  leading `-source-paths` flag confuses the dev argv strip), so it used
  the bundled `bin/lgx` instead — same checks, same results.
- Task 6 extracted a shared `args/signature` helper (used by both
  `usage-line` and help's `task-line`) instead of duplicating the
  `<name>`/`[name]` rendering.
- Codex reviewed each task's commit; the only finding (P1 after Task 3:
  validation landed before execution wiring) was the planned mid-stack
  state and was resolved by Tasks 4–5, reviewed together and clean.
