# `lgx install --all` Implementation Plan

**Status: completed** (2026-09-25)

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `lgx install --all`, which fetches every dep declared anywhere in `lgx.edn` — the project `:deps`, every context's `:extra-deps`, and every task's `:extra-deps` — so a later `lgx --with <ctx> run` or `lgx <task>` finds a warm cache.

**Tech Stack:** let-go (Clojure dialect, `.lg`), bash e2e harness (`tests/e2e.sh`).

---

## Design

### Why

`lgx install` resolves one basis: the project `:deps` plus whatever the CLI
`--with` names. A project with a `:ci` context and a `deploy` task carrying
their own `:extra-deps` needs one `install` per layer to warm the cache, and
the user has to know every name. The README roadmap already lists
`lgx install --all - fetch deps from all contexts and tasks in lgx.edn`.

### Semantics

`--all` runs **two resolution passes**:

1. **Base pass** — exactly today's `install`: project `:deps` merged with the
   CLI `--with` overlay, normal (first-wins) mode, `warn-all?` true. Its Go
   coords feed `apply-runtime!`, unchanged.
2. **Extras pass** — the project `:deps` pairs plus every `:extra-deps` coord
   pair from every effective context and every task
   (`config/extra-dep-pairs`), minus the pairs already in the base list,
   resolved in **all mode**. The project pairs are candidates too because a
   `--with` context can override a project lib's coord in the base pass
   (`merge-coords` replaces it in place); without them, `--with ci install
   --all` would never fetch the project's own coord for that lib.

**All mode fetches every distinct coord, not one coord per lib.** Two contexts
pinning the same lib at different shas both get fetched: that is the only
definition under which "warm for every context and task" holds. Transitive
closures are walked as usual. All mode may therefore fetch a transitive coord
that a real basis would override at top level. That is a harmless superset —
the cache is content-addressed — and the docs say so.

The runtime is warmed for the base basis only. A context's or task's Go coords
are partitioned out of the extras pass and discarded: under `:built` they would
key a runtime no command uses, and under `:installed` `install` is not the
command that would run them, so they are ignored rather than rejected. Context
Go deps build a runtime on first use, as today.

`--with` combined with `--all` is accepted and validated as usual (an unknown
name still errors); its deps are in the base pass and subsumed by the union.

### Resolver changes (`ensure-all!` in `lgx.lg`)

Today `ensure-all!` keeps `seen` as `{lib id}` and writes every warning line
to stderr as it walks. Two changes:

- **`seen` becomes `{lib [id ...]}`.** In normal mode a lib holds at most one
  id and the existing conflict rule applies (`(contains? seen lib)` skips; a
  differing id warns `already resolved as ...; ignoring ...`). In all mode an
  entry is skipped only when its id is already in the lib's vector, and the
  conflict warning never fires — there is no single basis to conflict in.
  Adding an id: `(assoc seen lib (conj (or (get seen lib) []) id))`.
- **Warnings become data.** `ensure-all!` no longer writes to stderr. It
  returns, in addition to `:installs`/`:go-coords`/`:go-origins`:
  - `:warnings` — the inline lines (Go split warnings, the conflict warning),
    in walk order, each ending in `\n`.
  - `:resolved` — `[[lib id] ...]` pairs flattened from `seen`
    (`(mapcat (fn [[lib ids]] (map (fn [id] [lib id]) ids)) seen)`).
  - `:pending` — the deferred declared-dep warning entries, as today.

  A new `report-resolution! [result warn-all?]` prints `:warnings` then the
  unresolved-declared lines (`emit-warnings!` renamed and re-parameterized to
  take `resolved` pairs, `pending`, `warn-all?`). Every existing caller
  (`basis`, `cmd-install`) calls `ensure-all!` then `report-resolution!`, so
  behaviour is byte-for-byte unchanged for every command except `install
  --all`.

`ensure-all!` signature: `[project coords opts]` where `opts` is
`{:all? bool}`. The old positional `warn-all?` moves to `report-resolution!`,
where it is used.

`config/unresolved-declared` switches from `(keys resolved)` to
`(map first resolved)` so it accepts pairs and maps alike; its existing tests
pass maps and keep working.

### `cmd-install` with `--all`

```
parse args (cli/parse-install-args) -> {:all? bool}, exit 1 on a bad token
find project, load config, with->overlay!, base coords (as today)
extras = (when all?
           (remove (set coords)
                   (distinct (concat (config/coords cfg)
                                     (config/extra-dep-pairs cfg)))))
header: "Installing dependencies..." or
        "Installing dependencies (all contexts and tasks)..."
if (and (empty? coords) (empty? extras))
  -> println "no deps in lgx.edn"; basis = {:go-coords [] :go-origins {}}
else
  base   = (when (seq coords) (ensure-all! project coords {:all? false}))
  report-resolution! base true                      ; as today
  extra  = (when (seq extras) (ensure-all! project extras {:all? true}))
  report extras: print (:warnings extra) lines not already printed by base,
                 then unresolved-declared over
                 (concat (:resolved base) (:resolved extra)) with
                 (:pending extra), warn-all? true, minus lines base printed
  installs = (concat (:installs base) (:installs extra))
  print-installs! installs, or "all deps up to date" when none :installed?
  basis = {:go-coords (:go-coords base) :go-origins (:go-origins base)}
apply-runtime! cfg basis :warn false               ; as today
install-letgo-source! cfg                          ; as today
```

Using the union of both passes' `:resolved` for the extras' unresolved check is
what keeps a context dep that declares a lib the project pins at top level
silent, exactly as it is in the real `--with` basis. Deduping against the base
pass's printed lines (a `distinct` over the concatenated line vectors, or a
set of base lines) means each warning prints once.

To make that dedupe simple, `report-resolution!` is built on a pure
`resolution-lines [result warn-all?] -> [line ...]`; `report-resolution!`
writes them. `cmd-install --all` computes both line vectors and writes
`(distinct (concat base-lines extra-lines))`, where `extra-lines` is computed
with the union `:resolved`.

### Config accessor

`config/extra-dep-pairs [cfg]` (pure, next to `contexts`):

- every effective context (`(config/contexts cfg)`), sorted by name, its
  `(dep-pairs (:extra-deps ctx))`;
- then every task (`(config/tasks cfg)`), sorted by name, its
  `(dep-pairs (:extra-deps task))`;
- concatenated, `distinct` (identical `[lib coord]` pairs collapse; a
  differing coord for the same lib survives — that is the point).

A task's `:with` names contexts already covered, so it is not re-read. Shipped
defaults carry no deps and contribute nothing. Project `:deps` are **not**
included: they are the base pass's job.

### CLI

`cli/parse-install-args [args]` → `{:all? bool}`. `--all` may repeat; any other
token throws `ex-info` with
`lgx: install does not take arguments other than --all`. `cmd-install` catches
it like `cmd-nrepl` does (message to stderr, exit 1). Today `lgx install junk`
is silently accepted; this tightens it.

`run-builtin!` passes `(vec rest-args)` to `cmd-install`, whose signature
becomes `[forward-args with]`.

### Output

- Header (stderr, green): `=> Installing dependencies...` or, under `--all`,
  `=> Installing dependencies (all contexts and tasks)...`.
- One combined install block on stdout: `installing N dep(s)...`, a line per
  fresh dep from either pass, `done`; or `all deps up to date`.
- `no deps in lgx.edn` only when both the base and the extras are empty.

### Out of scope

A per-layer report (`context :ci -> ...`), warming a runtime per context, and
flag completion (`completion.lg` never completes flags).

## Completion summary

**Implemented.** `lgx install --all`: `cli/parse-install-args` (rejects any other arg),
`config/extra-dep-pairs`, a pair-friendly `config/unresolved-declared`, an all
mode for `ensure-all!` (`seen` is `{lib [id ...]}`, every distinct coord
fetched, no conflict warning) that returns warnings as data
(`resolution-lines` / `report-resolution!`), and the two-pass `cmd-install`
with one combined install block and warnings deduped across passes. There is a
help row, e2e Scenarios 156-158 (520 assertions, up from 492), and README and
ARCHITECTURE updates. Verified end to end with the bundled binary: after
`install --all`, `--with ci run` needs no fetch.

**Issues.** The Task 4 codex review found a real gap: subtracting the base
pairs from the extras pass left a base dep's losing transitive coord unfetched,
and a context that replaces the winner needs that coord. Fixed by re-walking
the base pairs in all mode; Scenario 158 covers it and fails on the pre-fix
commit. The other codex rounds found nothing.

**Deviations (all).**
- Task 3: all mode also drops Go split conflict warnings, since the pass's Go coords are discarded anyway.
- Task 4: extras live in an `install-extras` helper. The extras pass walks base + project + extra pairs rather than extras minus base (codex must-fix).
- Task 5: added Scenario 158. `deploy` runs `{:run "main.lg"}`, since a `:sh` step never resolves deps. Added a `--with ci install --all` dedupe assert. The scenarios sit under `supports_source_paths`.
- Task 6: ARCHITECTURE explains the base re-walk.
- Task 7: lint and fmt-check failures are pre-existing on master and unchanged.

**What the plan could have specified better:** the design's "extras minus
base pairs" assumed a first-wins base walk had already fetched everything
below the base coords. It hadn't: a skipped losing coord is exactly what a
context override needs. The plan also used a `:sh` task for a warm-cache
check, and `:sh` never resolves deps.
