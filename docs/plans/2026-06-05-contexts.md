# `:contexts` + `--with` / `:with` Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a top-level `:contexts` key — named, reusable overlays of `:extra-deps`/`:extra-paths` — that any command can pull in via a global `--with dev,test` flag, and that a task can declare with `:with [:dev]`.

**Tech Stack:** let-go (Clojure dialect, `.lg`), bash e2e harness.

---

## Design

### Concept

A **context** is a named overlay holding only `:extra-deps` and `:extra-paths`.
It is the same shape as today's per-task inline extras, lifted to the project
top level and given a name so it can be reused across commands and tasks.

```edn
{:deps  {a {:git/url "…a" :git/tag "v1"}
         b {:git/url "…b" :git/tag "v1"}}
 :paths ["src"]

 :contexts
 {:dev  {:extra-paths ["dev"]
         :extra-deps  {nrepl {:git/url "…nrepl" :git/tag "v1"}}}
  :test {:extra-paths ["test-support"]}}

 :tasks
 {:repl {:doc  "REPL with dev tooling"
         :with [:dev]                  ; pull in the :dev overlay
         :do   [{:run "dev/repl.lg"}]}}}
```

Two ways to apply contexts:

- **Global flag** `lgx --with dev,test <command>` — applies to `run`, `build`,
  `test`, `install`, and custom tasks. `install` pre-fetches the named
  contexts' deps.
- **Task key** `:with [:dev]` — a task always runs with those contexts. A
  global `--with` on the same invocation is **unioned** on top.

Contexts and tasks remain orthogonal: a task keeps its inline
`:extra-deps`/`:extra-paths` (an anonymous, task-private overlay); `:with`
adds *named* overlays alongside it.

### Layering model (governs all merging)

Lowest → highest precedence. On a dep-name collision the higher layer's coord
wins (**last-wins**); paths concatenate in this order with project paths first,
so project namespaces still shadow lib namespaces:

```
1. project :deps / :paths             (base)
2. task :with contexts, in order       (only when running a task)
3. CLI --with contexts, in order       (the global flag)
4. task :extra-deps / :extra-paths     (inline, highest — hand-written for the task)
```

For `run`/`build`/`test`/`install` there is no task, so only layers **1 + 3**
apply. Mechanically this is the existing helpers, folded:

```
final-coords = (reduce config/merge-coords  project-pairs
                       [<ctx layers, in order>  <inline-extra pairs>])
final-paths  = project :paths ++ each layer's :extra-paths ++ inline   (dedup, keep first)
```

then handed to the existing `basis` → `ensure-all!`. `merge-coords` already
means "extra wins in place, new appended," so folding it left-to-right yields
last-wins for free. A worked example:

```
project :deps     {a v1, b v1}
+ ctx :dev         {b v2, c v1}      ; --with dev,test
+ ctx :test        {c v2, d v1}
+ task :extra-deps {a v3}
= a v3 (task wins) · b v2 (dev > project) · c v2 (test > dev, last) · d v1
```

### Components

- **`lgx/config.lg`** — owns context schema + validation and pure overlay
  resolution:
  - `:contexts` added to allowed top-level keys.
  - `validate-contexts!` — map of keyword → overlay; overlay allows only
    `:extra-deps`/`:extra-paths`, reusing `validate-paths!` and the existing
    extra-deps map check.
  - `validate-task!` gains `:with` (vector of keywords); each name must be a
    defined context. The set of defined names is computed in
    `validate-config!` and threaded into task validation, so a typo fails at
    config-load.
  - `config/contexts` accessor (returns the `:contexts` map or `{}`).
  - `config/context-overlay [contexts-map names]` — pure: resolves an ordered
    name list to `{:deps-pairs <combined> :paths <combined>}`, folding overlap
    among the named contexts last-wins; throws on an unknown name (carrying the
    defined names).

- **`lgx/cli.lg`** (new) — pure argv parsing, isolated so it is unit-testable
  (it cannot live in `lgx.main`, whose load runs `(main)`):
  - `cli/user-args [argv]` — the dev-vs-bundle program-prefix strip, moved
    verbatim from `lgx.main`.
  - `cli/parse-leading-flags [args]` → `{:verbose? bool :with [kw…] :args [str…]}`.
    Consumes leading `--verbose` and `--with a,b` tokens in any order,
    repeatable, up to the first non-flag token (the command). Comma-splits
    `--with` values, trims blanks, and throws on a `--with` with no value or
    only blanks.

- **`lgx.lg`** — wiring only. `main` runs `cli/parse-leading-flags
  (cli/user-args os/args)`; `dispatch` threads the CLI `:with` names to the
  basis commands. A single `overlay-basis` helper builds the layered
  coords/paths (CLI names ∪ task `:with`, then inline task extras) and calls the
  existing `basis`. An unknown CLI context name prints
  `lgx: unknown context :x (defined: …)` (or `(no contexts defined in lgx.edn)`)
  and exits 1.

### Validation & errors

- Validation order in `validate-config!`: validate `:contexts` first, collect
  the defined names, then validate `:tasks` with that set.
- Overlay with an unknown key (typo) → loud failure, same style as tasks.
- Task `:with [:typo]` → `lgx.edn: task :t references unknown context :typo
  (defined: :dev, :test)` at config-load.
- Runtime `--with typo` → `lgx: unknown context :typo (defined: :dev, :test)`
  / `(no contexts defined in lgx.edn)`, exit 1.
- `--with` with no value / only blanks → `lgx: --with requires a
  comma-separated list of context names`, exit 1.
- Dependency `lgx.edn` files are unaffected: `coords-at` still reads only a
  dep's `:deps`, never its `:contexts`.

### Testing strategy

- **Unit `test/lgx/config_test.lg`** — `:contexts` validation (accept good /
  both keys / empty overlay; reject non-map, non-keyword name, unknown overlay
  key, bad coord, `..` path); `context-overlay` (names → combined deps-pairs +
  paths in order; overlapping contexts last-wins; unknown name throws); `:with`
  validation (accept defined; reject unknown context, non-vector,
  non-keyword element).
- **Unit `test/lgx/cli_test.lg`** (new) — `parse-leading-flags`: bare command;
  `--verbose`; `--with a,b`; repeated `--with`; `--verbose` + `--with` both
  orders; comma-split with blanks trimmed; missing value throws; stops at first
  non-flag (flags after the command stay in `:args`). `user-args`: dev-prefix
  vs bundle-prefix.
- **E2E `tests/e2e.sh`** — reuse the hermetic `file://` bare-repo seeding and
  `supports_source_paths` gating:
  1. `lgx --with dev run` resolves a ns provided only by `:dev`'s
     `:extra-paths`.
  2. `lgx --with libctx run` cold-fetches a context `:extra-deps` git lib
     (assert `installing 1 dep(s)...` + script output).
  3. task `:with [:dev]` resolves the context's paths.
  4. union: task `:with [:dev]` + CLI `--with other` both apply.
  5. unknown `lgx --with typo run` → exit 1 + message; task `:with [:typo]` →
     config validation error.
- **Docs** — new README `### Contexts (:contexts)` section + the
  `--with`/`:with` surface; `ARCHITECTURE.md` overlay note in the basis +
  `lgx <task>` sections; tick both roadmap items.
